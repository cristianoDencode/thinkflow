# File storage

Every **user file** that must survive and be served back goes to the object store. Choose the
driver with `STORAGE_DRIVER`:

- `local` (default): files under `DATA_DIR/objects` (or `STORAGE_LOCAL_DIR`);
- `s3`: an S3-compatible bucket, such as the optional MinIO of the Compose `minio` profile.

| Goes to the object store                                          | Stays outside (SQLite or local disk)                                                                                   |
| ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Generated reports (HTML, Markdown, PDF): `reports/`               | SQLite: metadata, conversations, search index, settings                                                                |
| Originals uploaded to the Library: `library/`                     | Secrets: `secret.key`, NotebookLM credentials                                                                          |
| Test sessions (step screenshots, annotated, failures): `tests/`   | Reproducible caches: `tessdata`, Chromium, the Mermaid vendor bundle                                                   |
| Prototypes (versions, assets, thumbnails, renders): `prototypes/` | Temporary files (`notebooklm/tmp`, logins) and small data embedded in records (template logo, chat attachment excerpt) |
| Future modules (documents, images): `documents/`, `images/`       |                                                                                                                        |

Keys follow `<STORAGE_PREFIX><namespace>/<ids generated by the app>/<file>`, never the user's file
name. The set of namespaces is `OBJECT_NAMESPACES` in
`apps/server/src/shared/kernel/scoped-object-store.ts`.

**Adding a module that stores files**: register its namespace in `OBJECT_NAMESPACES`, create a
store in `app.ts` with `scopeObjectStore(objectStore, config.storage.prefix, '<namespace>')` and,
inside the context, a semantic adapter on top of it (like the library's
`ObjectDocumentFileStore`). Each module then sees only its own keys. See
[ADR 0002](adr/0002-sqlite-and-pluggable-object-store.md).

## Settings

All variables are listed in [configuration.md](configuration.md). The main ones:
`STORAGE_DRIVER`, `STORAGE_LOCAL_DIR`, `STORAGE_PREFIX` (lowercase folders ending in `/`, to share
a bucket between environments), `STORAGE_MAX_OBJECT_MB` and the `S3_*` family. For S3,
`S3_ACCESS_KEY_ID` and `S3_SECRET_ACCESS_KEY` also accept a `_FILE` variant (Docker or Kubernetes
secrets). Use a dedicated application user, never the MinIO root.

## MinIO with Docker Compose

The `minio` profile adds a local MinIO and a one-shot `minio-init` that creates a private bucket,
removes anonymous access, creates a least-privilege policy (`thinkflow-rw`) and an application user.
Images are the free Chainguard ones, pinned by digest (override with `MINIO_IMAGE` and `MC_IMAGE`).
Requires Docker Compose 2.20 or newer.

Full stack (in `.env`): `COMPOSE_PROFILES=minio`, `STORAGE_DRIVER=s3`, a long
`MINIO_ROOT_PASSWORD` and a long `S3_SECRET_ACCESS_KEY`, then:

```bash
docker compose up -d --build
```

Development (app on the host, MinIO in Docker):

```bash
docker compose --profile minio up -d --wait minio
docker compose --profile minio run --rm minio-init
STORAGE_DRIVER=s3 S3_ENDPOINT=http://127.0.0.1:9000 S3_BUCKET=thinkflow \
  S3_ACCESS_KEY_ID=thinkflow S3_SECRET_ACCESS_KEY=your-secret pnpm dev
```

More details (images, production hardening, key rotation) are in
[`deploy/minio/README.md`](../deploy/minio/README.md).

## Switching from local to S3

After configuring S3 and running `minio-init`:

```bash
pnpm --filter @thinkflow/server storage:migrate --dry-run
pnpm --filter @thinkflow/server storage:migrate
```

The first command shows what would be copied. The command copies `DATA_DIR/objects` (or
`STORAGE_LOCAL_DIR`) to the bucket with the same keys, is idempotent, never deletes the source and
also moves uploads left in `DATA_DIR/library` by older versions. Inside the Docker image, run
`docker compose exec thinkflow node dist/storage-migrate.js`. Check the application, then delete the
local folder.

## Backup

Always back up the SQLite file and `secret.key` (or keep `THINKFLOW_SECRET` safe). With the local
driver also back up `DATA_DIR/objects`; with S3, back up the bucket (for example with `mc mirror`).
